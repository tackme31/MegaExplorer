# 受信箱 — 要望・機能追加・不具合

**思いついたことをそのまま書き足す場所。** `/evolve` ループが毎サイクルの最初にここを読み、
`docs/ROADMAP.md` へ反映してから、この行を消す。**ROADMAP.md を直接編集する必要はない。**

書き方は**自由記述の箇条書き**、1 件 1 項目。サイズ・優先度・置き場所は決めなくてよい（それを
決めなくて済むのがこのファイルの存在理由）。決めたいときだけ下のラベルを頭に付ける。

置き場は **`develop`**（開発の幹。`master` はリリース済みの版専用）。書いたら**コミットまで
済ませること**——未コミットの変更が残っていると次のサイクルは冒頭のワーキングツリー検査で中止する（安全側に倒れるだけだが、その周は無駄になる）。
サイクル実行中にコミットすると、その周の `git merge --ff-only` が拒否される。通常マージすれば
済むだけで、対処は `CLAUDE.md` の「Loop engineering」にある。

## 付けられるラベル（全部任意）

| ラベル | 意味 |
|---|---|
| `[バグ]` | ROADMAP の種類欄が「不具合」になる。**再現手順を書くこと**。優先度は別で、`[高]` `[中]` `[低]` が無ければ「中」 |
| `[最優先]` | そのセクションの先頭に置く。**これが無い限り、ループは末尾にしか追加しない** |
| `[高]` `[中]` `[低]` | 優先度セクションの指定。無ければ「中」の末尾 |
| `[削除]` | ROADMAP から消す。どの項目かわかるように書く |
| `[編集]` | 既存項目の書き換え・メモの追記。どの項目かわかるように書く |

ラベルなしの新規要望は「優先度: 中」の末尾に入る。**早く着手してほしいものは必ずラベルを付ける**
——ループは自分で置いた行を既存の行より上には置かない（優先順位を決めるのは人間だけ、という
線引きのため）。

## ループ側の約束

- **サイズは付けるが、分割はしない。** 画面 1 つ分以上ありそうなものは `L` として登録し、
  ROADMAP の既存ルール（L は着手する周が S/M へ割り、そのまま先頭を実装する）に任せる。
- **意味が取れなかったら推測しない。** その行は消さずに残し、末尾に
  `← 解釈できませんでした（理由）` を付けて報告に書く。印の付いた行は次の周から読み飛ばすので、
  書き直すときはその印ごと消すこと。
- **取り込んだ行は消える。** 消えていれば ROADMAP に入ったということ。何がどう入ったかは
  サイクルの報告に出る。

  **SDK 調査は済んでいる（2026-09-09）。4 つとも API はある:**
  - リンク取得 — `MegaNode::getPublicLink(bool includeKey)`（`megaapi.h:1426`）。エクスポート
    済みならローカルで取れる（通信なし）。未エクスポートなら `exportNode` の戻り値。
  - 有効期限 — `exportNode(node, expireTime, ...)` の第 2 引数（Unix 秒、0 = 無期限）。読み戻しは
    `MegaNode::getExpirationTime()`（0 = 無期限、-1 = 未エクスポート）。既にリンクのあるノードでも
    違う ets で呼び直せば更新される（`megaclient.cpp:14538` の短絡条件が ets 一致を要求している）。
    **無料アカウントでは `API_EACCESS` で失敗する** — SDK の統合テスト `ExportNodeWithExpiryDate`
    （`third_party/sdk/tests/integration/SdkTest_test.cpp:21479`）が free で EACCESS、PRO I で成功、と
    明示的に検証している。
  - パスワード — `encryptLinkWithPassword`（`megaapi.h:14855`）。中身は `MegaClient::encryptlink`
    （`megaclient.cpp:14786`）で、ソルト＋派生鍵でリンク鍵を XOR して `#P!` 文字列を組み立てる
    **完全ローカル処理・通信ゼロ**。よって無料アカウントでも動くが、代わりに**サーバーに何も
    残らないので「このリンクにパスワードが付いているか」を後から問い合わせる API が無い**。
  - リンク削除 — `disableExport` は実装済み（`FileMutationController::removeLink`）。ダイアログ
    からはそれを呼ぶだけ。
  - 参考: 本家画面の「リンクアクティビティ」（閲覧数・DL 数）と「音声を埋め込む」に相当する API は
    SDK に無いので、この 2 つは対象外。

  **UI の決定事項:**
  - 縦 1 枚、幅 480px 前後。上から ①ファイル名（`FileIcon` ＋名前）②リンク欄（読み取り専用

    ③④は区切り線で分ける。`PropertiesDialog` と同じく `parent: Overlay.overlay` / `modal: true`。
  - **有効期限はトグル即適用**（`SettingsDialog` と同じ流儀）。読み戻せる本物の設定なので、開いた
    ときのトグル初期値は `getExpirationTime()` から作る。本家の「変更内容を保存」ボタンは置かない。
    トグル ON で日付ピッカーが現れ、OFF なら ets = 0 で呼び直す。
  - **パスワードは「保存」ではなく「作成」**。読み戻せないので開くたび必ず OFF から始まる。作成すると
    ②のリンク欄の中身が `#P!…` に差し替わり、コピー先は常に 1 つに保つ。トグル OFF で元のリンクに戻る。
