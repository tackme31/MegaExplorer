# 受信箱 — 要望・機能追加・不具合

**思いついたことをそのまま書き足す場所。** `/evolve` ループが毎サイクルの最初にここを読み、
`docs/ROADMAP.md` へ反映してから、この行を消す。**ROADMAP.md を直接編集する必要はない。**

書き方は**自由記述の箇条書き**、1 件 1 項目。サイズ・優先度・置き場所は決めなくてよい（それを
決めなくて済むのがこのファイルの存在理由）。決めたいときだけ下のラベルを頭に付ける。

置き場は **`develop`**（開発の幹。`master` はリリース済みの版専用）。書いたら**コミットまで
済ませること**——未コミットの変更が残っていると次のサイクルは冒頭のワーキングツリー検査で中止する（安全側に倒れるだけだが、その周は無駄になる）。
サイクル実行中にコミットすると、その周の `git merge --ff-only` が拒否される。通常マージすれば
済むだけで、対処は `CLAUDE.md` の「Loop engineering」にある。

## 付けられるラベル（全部任意）

| ラベル | 意味 |
|---|---|
| `[バグ]` | ROADMAP の種類欄が「不具合」になる。**再現手順を書くこと**。優先度は別で、`[高]` `[中]` `[低]` が無ければ「中」 |
| `[最優先]` | そのセクションの先頭に置く。**これが無い限り、ループは末尾にしか追加しない** |
| `[高]` `[中]` `[低]` | 優先度セクションの指定。無ければ「中」の末尾 |
| `[削除]` | ROADMAP から消す。どの項目かわかるように書く |
| `[編集]` | 既存項目の書き換え・メモの追記。どの項目かわかるように書く |

ラベルなしの新規要望は「優先度: 中」の末尾に入る。**早く着手してほしいものは必ずラベルを付ける**
——ループは自分で置いた行を既存の行より上には置かない（優先順位を決めるのは人間だけ、という
線引きのため）。

## ループ側の約束

- **サイズは付けるが、分割はしない。** 画面 1 つ分以上ありそうなものは `L` として登録し、
  ROADMAP の既存ルール（L はそのまま着手せず、1 周かけて S/M へ割る）に任せる。
- **意味が取れなかったら推測しない。** その行は消さずに残し、末尾に
  `← 解釈できませんでした（理由）` を付けて報告に書く。印の付いた行は次の周から読み飛ばすので、
  書き直すときはその印ごと消すこと。
- **取り込んだ行は消える。** 消えていれば ROADMAP に入ったということ。何がどう入ったかは
  サイクルの報告に出る。

- 失敗したときのメッセージが実態に合っておらず、原因が分からない（2 点まとめて）
  (a) 転送量・容量の超過（`EOVERQUOTA` = -17）が `src/mega/MegaErrorCodes.h` に無いため
      `Unknown` に落ち、SDK の英語文字列がそのまま出るか、何も出ない。無料アカウントは
      転送量制限に日常的に当たるので、試した人が最初に踏む可能性が高い
  (b) `BulkOperationRunner` が `errorCode` を破棄して件数だけ通知するので、容量超過も
      権限不足も通信失敗も、全部「Failed to move 3 item(s)」という同じ文面になる。
      ダウンロード／アップロード側も同様
  代表的なエラーコードだけでも文面に反映したい

- アップロードの同名衝突ダイアログだけ、既定ボタンとフォーカスが未指定
  `qml/components/NameConflictDialog.qml:118-154` の `DialogButtonBox` は
  `Replace` / `Skip` / `Cancel` の 3 ボタンに `highlighted` もフォーカス指定も無い。
  左端が Replace（＝上書き。版管理 OFF なら旧ファイルは復元不能）なので、
  Enter や Tab の挙動がプラットフォーム任せになる。
  対になる `qml/components/CopyConflictDialog.qml` は `markDefaultAnswer()` で
  既定とフォーカスを明示し、データを失う場合だけ既定を安全側へ倒しているので、
  同じ関数を移植して版管理 OFF のときは `Skip` を既定にしたい（2 ダイアログで共有してよい）

- ビルドの前提が README に書かれておらず、他人の環境で configure が失敗する
  (a) vcpkg の triplet が `VCPKG_PLATFORM_TOOLSET v142` を指定しているが、v142 は
      VS2022 の「C++ によるデスクトップ開発」ワークロードの既定に入っていない
  (b) `find_visual_studio_path.cmake` が `C:\Program Files\...\2022\*` の 3 パスを直書きしていて、
      Build Tools のみの環境や C ドライブ以外だと失敗する
  (c) README の手順 4 が素の `cmake` を使っている（Strawberry Perl の 3.29 を拾って
      `CMakeCache.txt` を壊す罠。`CLAUDE.md` に既出）

- [低] exe にバージョン情報リソース（VERSIONINFO）が無い
  `resources/appicon.rc` はアイコンのみで、`FileVersion` / `ProductVersion` / `CompanyName` が空。
  バージョンを重ねて配布するなら、受け取った exe のプロパティで版が分かるようにしたい
  （不具合報告のときに効く）。`CMakeLists.txt:3` の `project(... VERSION 0.1.0)` から流し込める
