# ROADMAP

**このリポジトリで次に何を実装するかを決める唯一のバックログ。** `/evolve` ループが毎サイクル
最初に読み、ここから 1 件選んで実装する。

**要望・機能追加・不具合は `docs/REQUESTS.md`（受信箱）に自由記述で書く。** ループが毎周それを
読んでこの表へ反映するので、**このファイルを人間が直接編集する必要はない**。書き込むのがループ
だけであれば、サイクルが完了行を消すのと人間の編集が同じ行を取り合うこともない。

## 運用ルール

1. **上から順に着手する。** セクション順（バグ修正 → 高 → 中 → 低）、セクション内は表の上から。
   飛ばすのは「サイズ **L**」「`blocked`」「前提が未達」のときだけで、その理由を報告に書く。
2. **書くのは「満たすべき機能」であって、実装方法ではない。** 項目名とメモは
   **何ができるようになれば完了か**を述べる場所で、ファイル名・関数名・クラス設計・手順といった
   実装の具体は書かない —— それを決めるのは着手する周が現物のコードを読んでからで、先に書くと
   古びるうえ判断も縛る。例外は**在り処の手掛かり**だけ（`evolve/NNN` が残した穴、`STUDY_*.md`
   へのリンク、既存仕様のどこが変わるか）。受信箱から取り込むときも同じ。
3. **完了したら行をこの表から消し、`docs/roadmap-done.md` に 1 行足す。** 両方に残さない。
4. **`blocked` は「やらないと決めた」か「今は着手できない」。** 必ずメモ欄に理由を書く。
   `blocked` の行はループが勝手に `todo` へ戻さない — 戻すのは人間だけ。
5. **サイズ L はそのまま着手禁止。** その周は「L を S/M へ分割して表を書き換えるだけ」で終わらせ、
   実装は次の周に回す。分割の前に、メモ欄にリンクした `docs/investigations/STUDY_*.md` を読む。
6. **不具合と機能追加を分ける基準は「意図と実装が一致しているか」**——深刻度でも、直す手間でも
   ない。
   - **不具合**（→「バグ修正（最優先）」節）＝ **既に実装した機能が、実装した周が意図した振る舞い
     をしていない。** 誰もそう動くつもりが無かった挙動のこと——文字化け、表示が古いまま残る、
     押しても何も起きない、落ちる、状態が別のタブへ漏れる、等。
   - **機能追加**（→「優先度: 高 / 中 / 低」）＝ **今の挙動は意図どおりだが、それでは足りない。**
     まだ書いていない振る舞いを新しく足す話。
   - 迷ったら **「その挙動を、それを入れた周の完了条件として書けたか」** を問う。書けない
     （＝誰も望んでいない）なら不具合。書けるが物足りないだけなら機能追加。
   - **「動きはするので後回しでよい」は分類の理由にならない。** 回避策があること・実害が小さい
     こと・修正が M や L になることは、どれも不具合を優先度セクションへ置く理由にならない。
     深刻度と手当ての順序はメモ欄に書く（サイズ L の不具合も節は動かさず、5. のとおり分割する）。
7. **サイクル中に気づいた意図しない挙動は、その周で直さないなら「バグ修正（最優先）」へ起票する。**
   実装中・検証中・レビュー中・実機確認中のどこで気づいたかを問わない。6. の基準で不具合なら
   行き先はバグ節ひとつだけで、**「優先度: 中」に入れて機能追加のように見せない**。メモ欄には
   **再現手順**と**気づいた周（`evolve/NNN`）**を書く。原因が未特定でも起票する（未特定だと書く）。
8. **バグ・要望の入口は `docs/REQUESTS.md`。** GitHub issue は使わない（双方向の同期コストに
   見合わないため）。受信箱は人間が書きループが消すだけの一方向なので、その同期は要らない。
   長い診断が要るものだけ `docs/investigations/BUG_*.md` を起こし、ここからリンクする。
9. **このリポジトリで実装しないもの**は「見送り (blocked)」節にある。ループはそこへ着手しないだけ
   でなく、**関連する機能を新たに提案することもしない**。

## 凡例

| サイズ | 目安 | 意味 |
|---|---|---|
| **S** | 1 時間相当 | 1 ファイル〜数ファイルの局所的な変更。設計判断がほぼ要らない |
| **M** | 半日相当 | 複数レイヤに跨るが、既存の型と画面の枠内に収まる |
| **L** | 要分割 | 画面 1 つ分以上、または新しい抽象が要る。**そのまま着手しない** |
