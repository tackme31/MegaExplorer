# ROADMAP

**このリポジトリで次に何を実装するかを決める唯一のバックログ。** `/evolve` ループが毎サイクル
最初に読み、ここから 1 件選んで実装する。

**要望・機能追加・不具合は `docs/REQUESTS.md`（受信箱）に自由記述で書く。** ループが毎周それを
読んでこの表へ反映するので、**このファイルを人間が直接編集する必要はない**。書き込むのがループ
だけであれば、サイクルが完了行を消すのと人間の編集が同じ行を取り合うこともない。

## 運用ルール

1. **上から順に着手する。** セクション順（バグ修正 → 高 → 中 → 低）、セクション内は表の上から。
   飛ばすのは「サイズ **L**」「`blocked`」「前提が未達」のときだけで、その理由を報告に書く。
2. **完了したら行をこの表から消し、`docs/roadmap-done.md` に 1 行足す。** 両方に残さない。
3. **`blocked` は「やらないと決めた」か「今は着手できない」。** 必ずメモ欄に理由を書く。
   `blocked` の行はループが勝手に `todo` へ戻さない — 戻すのは人間だけ。
4. **サイズ L はそのまま着手禁止。** その周は「L を S/M へ分割して表を書き換えるだけ」で終わらせ、
   実装は次の周に回す。分割の前に、メモ欄にリンクした `docs/investigations/STUDY_*.md` を読む。
5. **バグ・要望の入口は `docs/REQUESTS.md`。** GitHub issue は使わない（双方向の同期コストに
   見合わないため）。受信箱は人間が書きループが消すだけの一方向なので、その同期は要らない。
   長い診断が要るものだけ `docs/investigations/BUG_*.md` を起こし、ここからリンクする。
6. **このリポジトリで実装しないもの**は「見送り (blocked)」節にある。ループはそこへ着手しないだけ
   でなく、**関連する機能を新たに提案することもしない**。

## 凡例

| サイズ | 目安 | 意味 |
|---|---|---|
| **S** | 1 時間相当 | 1 ファイル〜数ファイルの局所的な変更。設計判断がほぼ要らない |
| **M** | 半日相当 | 複数レイヤに跨るが、既存の型と画面の枠内に収まる |
| **L** | 要分割 | 画面 1 つ分以上、または新しい抽象が要る。**そのまま着手しない** |

分割**された — `docs/investigations/SPEC_NAME_CONFLICT_COPY_MOVE.md`（以下 **CM**）と
`docs/investigations/SPEC_NAME_CONFLICT_UPLOAD.md`（以下 **UP**）。どちらの経路も残るのは
CM §6-1 だけで、それは実測待ちなので行を立てていない（下記）。

**コピー・移動の仕様は同日に API ファーストで書き直され、「置き換える」という選択肢そのものが
廃止された。** MEGA の API に「上書きする移動」は無く、同じ語が「SDK 任せ」「アプリ製の合成」
「実現不能」の 3 つを指していたのが、旧仕様が説明しにくい根本だった（経緯は CM §7）。選択肢は
経路×種別の 4 セル共通で「**このまま実行／名前を変えて実行／スキップ／キャンセル**」になり、
セルごとに変わるのは本文の説明文だけになる。

**移動の置き換えは `evolve/028` で撤去済み**（`copy` + `moveToRubbish` の合成が消え、移動は
`moveNode` 1 本になった）。**4 択は `evolve/029` で揃った**——「名前を変えて実行」が両経路に付き、
「このまま実行」は常時表示、`IMegaClient::moveNode` は `newName` を取る。ダイアログの 1 枚構成・
宛先スナップショット・バッチ計画・クリップボード連携はそのまま使う（CM §2-2・§5-2）。
**`evolve/030` で本文と既定ボタンも揃い、CM §3 は実装済みになった** — 版管理の有無は
`accountController.fileVersioningEnabled`（ログイン時に 1 回読む）で読む。
**CM §5-3（同一操作内の同名も衝突として数える）は `evolve/032` でコピー・移動側だけ入った** —
`FileMutationController::collidingEntries()` が 1 エントリ 1 フラグを返し、ダイアログの予告と
実際の計画が同じ判定を見る。**CM §1-6 は `evolve/034` で入った** — `IMegaClient::subtreeSize()`
（`MegaApi::getSize` の同期ラッパ）で衝突側と無傷側のバイト数を別々に数え、コピーのダイアログだけ
が引用する（移動はアカウントに何も足さないので添えない）。再帰的なファイル件数は添えていない：
SDK の `getNumChildFiles()` は直下しか数えず、再帰版の `getFolderInfo` はリクエストで同期に返らない。
CM 側に残るのは積み残しの §6-1（同名を 2 件「このまま実行」でコピーすると版が積み上がって 1 行に
見える件——実測してから文面か自動リネームかを決める）だけ。**§6-1 には仕様が書いていない側面が
`evolve/032` のレビューで 1 つ出た**: この 2 件は同じ名前・空の `newName` で**並列に発行される**ので、
どちらが最新版になるかはサーバ到着順まかせ＝非決定的になる。「1 行に見える」だけでなく「どちらの
中身が残るか決まらない」ので、決めるときは文面追加より 2 件目の自動リネーム寄りに読むこと。

アップロード側の仕様は分割前から変わっておらず、「名前衝突 1」は `evolve/025` で済んでいる。
**UP §5-1 の走査は `evolve/031` で入った** — `ILocalFileSystem`（`src/core`、1 階層ぶんの列挙）＋
`QtLocalFileSystem`（`src/platform`）＋ `UploadScanService`（両側に同名フォルダがある枝にだけ降り、
`UploadCollision` の一覧を返す）と `IMegaClient::findChildFolders`。**`evolve/033` で UI に配線され、
UP §3-1・§3-3・§5-2 は実装済みになった** — ダイアログはネストした重複も 1 枚に畳んで
`dir/sub/a.png` の形で並べ、重複 0 ならもう出ない。スキップは
`UploadScanService::planSkippingCollisions()` が返す計画（衝突のある枝だけ歩き、無い枝は
ディレクトリごと SDK に渡す）で発行する。**UP §1-6 も `evolve/034` で入った**（アップロード側の
バイト数はローカルなので SDK を使わず `QFileInfo` で数える）。**UP §6-1 は `evolve/035` で入り、
UP 側の積み残しは無くなった** — バッチ自身が 2 度持ち込む名前を（ハンドルではなく）名前で数え、

同名フォルダ同士**は依然として未検出で、これは「優先度: 中」に別項目として起こした。
**旧 `SPEC_NAME_CONFLICT_RESOLUTION.md` は `docs/archive/` へ退役した** — 読まないこと。
