# 共有リンクの設定画面 — 実装前調査

> **状態: 未着手。** `docs/ROADMAP.md`「優先度: 中」の 3 行（ダイアログ本体 / 有効期限 /
> パスワード）がここを参照する。SDK 側の可否は確認済みで、**4 機能とも API はある**が、
> 有効期限は **Pro 限定**、パスワードは **設定状態を読み戻せない**という 2 つの制約が UI の形を
> 決めている。実装・計測は行っていない机上調査。

2026-09-09。本家 Web のコンテキストメニュー「リンクを共有」から出る 2 画面（「リンクの共有」と、
そこから開く「リンク設定」）のうち、**リンクの表示・コピー / 有効期限 / パスワード / リンクの削除**
の 4 つを 1 枚のダイアログに畳めるか、を見た。本家にある「リンクアクティビティ」（閲覧数・DL 数）と
「音声を埋め込む」は SDK に対応する API が無いので対象外と判断した。

---

## 1. SDK 調査

### 1.1 リンクの表示・コピー — 可能、制約なし

`MegaNode::getPublicLink(bool includeKey)`（`third_party/sdk/include/megaapi.h:1426`）が
エクスポート済みノードからリンク文字列をローカルに返す（通信なし）。付随して
`getPublicLinkCreationTime()` / `isExpired()` / `isTakenDown()` も同じくローカル。
未エクスポートなら `exportNode` の結果としてリンクが返る（既存実装）。

`getPublicLink(false)` ＋ `getBase64Key()` で「復号キーを分けて送る」も作れるが、今回の対象外。

### 1.2 有効期限 — Pro 限定

`exportNode(node, expireTime, writable, megaHosted, listener)` の第 2 引数が Unix 秒で、`0` が
無期限。読み戻しは `MegaNode::getExpirationTime()`（`0` = 無期限、`-1` = 未エクスポート）。

既にリンクのあるノードでも、**違う ets で呼び直せば再発行される** —— `MegaClient::exportnode`
（`third_party/sdk/src/megaclient.cpp:14538`）の短絡条件が `ets == n->plink->ets` を含むので、
値が変われば `CommandSetPH` が飛ぶ。つまり期限の設定・変更・解除はすべて `exportNode` 1 本で足りる。

**無料アカウントでは `API_EACCESS` で失敗する。** SDK 自身の統合テスト
`ExportNodeWithExpiryDate`（`third_party/sdk/tests/integration/SdkTest_test.cpp:21479`）が、
free に落として EACCESS、PRO I に上げて成功、と明示的に検証している。推測ではない。

### 1.3 パスワード — 動くが、状態が残らない

`encryptLinkWithPassword` / `decryptPasswordProtectedLink`
（`third_party/sdk/include/megaapi.h:14855`）。中身は `MegaClient::encryptlink`
（`third_party/sdk/src/megaclient.cpp:14786`）で、ランダムソルトから鍵を派生し、リンク鍵を XOR して
HMAC を付け、`https://mega.nz/#P!<base64>` を組み立てるだけ。**完全にローカル処理で、通信が無い。**

ここから 2 つ帰結する。

1. **無料アカウントでも動く。** Pro 判定に引っかかりようがない。本家 Web が Pro 限定にしているのは
   製品判断であって SDK 制約ではない。
2. **サーバーに何も残らないので、「このリンクにパスワードが付いているか」を後から問い合わせる API が
   存在しない。** 本家 Web も同じ制約下にある。したがって永続的なトグルとしては表現できない。

もう一点、UI の文言に効く事実がある。`#P!` リンクは元のリンクを暗号化した**別の文字列**で、
**元のパスワードなしリンクを無効化しない**。本家の「パスワードでアクセスを制限します」という説明は
この点で誤解を招くので、真似しない。

### 1.4 リンクの削除 — 実装済み

`disableExport` は `MegaSdkClient`／`FileOperationService`／`FileMutationController::removeLink` まで
既にあり、確認ダイアログ（`ConfirmRemoveLinkDialog.qml`）も存在する。ダイアログからはそれを呼ぶだけ。

## 2. UI の決定（2026-09-09、依頼者と合意済み）

**2 画面を 1 枚に畳む。** 縦 1 枚、幅 480px 前後。上から ①ファイル名 ②リンク欄（読み取り専用＋
コピーボタン、下に説明 1 行）③有効期限 ④パスワード保護 ⑤フッター。③④は区切り線で分ける。

決め手は **§1.2 と §1.3 で 2 つの設定の性質が違う**こと。有効期限は読み戻せる本物のサーバー状態、
パスワードはその場限りの生成。本家はこれを同じ「変更内容を保存」ボタンの下に並べていて、違いを
隠してしまっている。そこで:

- **有効期限はトグル即適用**（`SettingsDialog` と同じ流儀）。開いたときの初期値は
  `getExpirationTime()` から作る。**「変更内容を保存」ボタンは置かない**ので、本家より 1 ステップ減る。
- **パスワードは「保存」ではなく「作成」。** 開くたび必ず OFF から始まる。作成すると②のリンク欄の
  中身が `#P!…` に差し替わり、**コピー先を常に 1 つに保つ**。トグル OFF で元のリンクに戻る。
  差し替え中は説明行を「パスワードなしの元リンクも引き続き有効です」に変えて、§1.3 の事実を隠さない。
  - 「元リンク欄とパスワード欄を 2 つ並べる」案と「パスワードだけ別ダイアログ」案も検討したが、
    ダイアログの主目的（1 本のリンクをコピーする）がぶれるので採らなかった。
- **Pro 限定の 2 つは無料アカウントでトグルを disabled。** 無効な理由が見えないと詰むので、説明行を
  「（Pro プランが必要です）」付きに差し替える。判定は既存の `AccountInfo::proLevel`。
  パスワードは §1.3 のとおり技術的には無料でも動くが、本家に合わせて同じ扱いにする（製品判断）。
- フッターは左端に破壊的な「リンクを削除」、右にプライマリの「リンクをコピー」と「閉じる」。
- **未エクスポートのノードで開いたら、開いた瞬間にリンクを作る**（本家と同じ）。取得中はリンク欄を
  ローディング表示に。
- 導線は既存の「リンクをコピー」（ワンクリックの近道）を残したうえで、その隣に新しい項目を足す。
  共有リンク一覧ビューの行からも同じものを開ける。

## 3. 分割（ROADMAP の 3 行に対応）

L 1 件では大きいので 3 つに割った。**1 が 2・3 の前提** —— ダイアログの器と、リンク文字列を UI まで
運ぶ経路が先に要る。

| # | 内容 | 目安 |
|---|---|---|
| 1 | ダイアログ本体。リンクの表示・コピーと、リンクの削除。未エクスポートなら開いた時点で作る | M |
| 2 | 有効期限。トグル＋日付、即適用、初期値の読み戻し、無料アカウントでの無効化 | M |
| 3 | パスワード。入力＋作成、リンク欄の差し替え、無料アカウントでの無効化 | M |

`IMegaClient` に足りない口は 3 つ: **リンク文字列と有効期限の取得** / **期限を指定できる
`exportNode`** / **パスワード暗号化**。現状の `exportNode` は expireTime を `0` 決め打ちにしている
（`src/mega/MegaSdkClient.cpp:1205`、その旨のコメントごと差し替えになる）。

## 4. 実機確認の注意

**テスト用アカウントが無料プランなら、有効期限の成功パスは実機で確認できない**（§1.2 のとおり
`API_EACCESS` で落ちる側しか見られない）。その場合は `docs/roadmap-done.md` のメモにそう書き、
実機確認の欄を人間に残すこと。
